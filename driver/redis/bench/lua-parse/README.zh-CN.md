# Redis Lua 单数字与三字段基准

可运行程序测量**当前**无版本前缀的 `tat:interval:burst`，与单数字 TAT 原型比较，
直接读取此 checkout 的 Lua。单数字原型去掉了策略冲突检测，**不是保持原契约的替代实现**。

在 Redis driver 模块目录中，连接**独立、可销毁的 Redis**：

```sh
go run ./bench/lua-parse -addr 127.0.0.1:PORT > results.json
go run ./bench/lua-parse -addr 127.0.0.1:PORT -iterations 200000 > results-200k.json
```

必须显式传地址，不要连接生产实例或并行运行：程序会覆盖/删除固定的
`bench:{lua-parse}:*` 键，并要求独占 EVALSHA 统计。需要 SCRIPT LOAD、EVALSHA、
INFO、TIME、GET、MSET 和 DEL。用 `--save '' --appendonly no` 启动临时 Redis，
不要改变已有服务的持久化配置。

## 方法

- 预热 3 轮不计入，再测 15 轮，按固定种子随机交错各方案。
- 使用 Redis `cmdstat_evalsha.usec` 差值，排除客户端/网络延迟。同一个脚本内
  两次 TIME 可能返回相同缓存时间，不能用作计时器。
- 微基准对 64 个活跃 TAT 循环 50,000 次，每次结果参与校验和。包含样本构造、
  循环/索引、函数调用和校验和开销；构造被摊薄，循环基线单列、不扣减。
- `scalar_parse` 使用 `tonumber`；`tuple_parse` 匹配三个十进制字段并逐个转换。
  reader 组还校验边界、分配状态表；三字段组校验 interval/burst。异常输入校验并不等价。
- 完整 Allow 组用真实脚本操作 1、4、32 个活跃额度。单数字原型替换读取/编码、
  移除策略检查，保留 GET、GCRA、MSET 和响应构造；这测量的**不只是解析**。
- 完整组每轮 pipeline 1,000 次，验证每条获准和 EVALSHA 调用数，刷新状态不计时。
  完整组 interval=1us、burst=1,000,000,000；微基准 interval=100,000us、burst=10。
- 报告各轮平均耗时的中位数，**不是请求 P50/P99**。包含 GC、分配、调度和虚拟机
  噪声，仅覆盖合法、活跃、热数据和始终获准路径。
- 可选的 200,000 次循环检查规模稳定性。这些是本地实验，不是线上吞吐承诺，
  也不是百万 QPS 容量的证明。

## 当前三字段测量（2026-10-28）

[原始结果](results-redis8-tuple.json) 记录 Lua SHA-256 和当前额度格式。
Apple M3 Pro / arm64、OrbStack Linux、Redis 8.10.2、关闭 RDB/AOF；
15 轮有效测量，微基准每轮 50,000 次，完整请求每个样本 1,000 次调用。

| 场景 | 单数字 | 当前三字段 |
|---|---:|---:|
| 解析 | 935.14 ns | 1285.60 ns |
| 读取及校验 | 1128.92 ns | 1512.82 ns |
| Allow，1 个额度 | 5.788 us | 6.804 us |
| Allow，4 个额度 | 14.455 us | 17.651 us |
| Allow，32 个额度 | 89.831 us | 112.976 us |

循环基线 37.54 ns。这与下面历史运行并非受控的前后对照，跨次差异不能归因于移除标签。

## 历史 Q2 测量（2026-10-28）

保留 [50k](results-redis8-valid.json) 和 [200k](results-redis8-200k.json) 原始数据作为
证据，被测源码是 `2820790`，程序提交是 `c331f56`。它们测的是**已移除的 Q2 格式**，
不代表当前三字段格式。旧程序可从 Git 查阅，当前程序不保留旧协议读取或执行分支。

Apple M3 Pro / arm64、OrbStack Linux、Redis 8.10.2、关闭 RDB/AOF。
有效 50k 结果的各轮平均耗时中位数：

| 历史微基准 | 单数字 | Q2 | Q2 额外耗时 |
|---|---:|---:|---:|
| 解析 | 851.80 ns | 1323.50 ns | 471.70 ns（+55.4%） |
| 读取及校验 | 1031.16 ns | 1540.14 ns | 508.98 ns（+49.4%） |

循环基线 35.18 ns。200k 复测：解析 887.40 / 1321.85 ns，读取校验
1053.91 / 1544.74 ns。

| 历史 Allow 服务端执行 | 单数字 | Q2 |
|---|---:|---:|
| 1 个额度 | 5.319 us | 6.234 us |
| 4 个额度 | 13.676 us | 16.846 us |
| 32 个额度 | 83.663 us | 109.052 us |

不能把这些历史差异全归因于删除前缀，或当作当前性能。单数字对照还删除了策略校验，
